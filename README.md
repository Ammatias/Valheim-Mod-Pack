# Valheim Mod Pack

Два независимых клиентских комплекта для **Midgard** и **Helheim**. Файлы модов хранятся в GitHub Releases, код лаунчера — в этом репозитории. Покупать Valheim второй раз не требуется.

Первый готовый выпуск: [2026.11.24.1](https://github.com/Ammatias/Valheim-Mod-Pack/releases/tag/pack-2026.11.24.1).

| Сборка | Первый запуск | Состав |
|---|---:|---|
| [Midgard](Midgard/) | около 785 МБ | 233 файла, 15 DLL в plugins |
| [Helheim](Helheim/) | около 618 МБ | 818 файлов, 44 DLL в plugins, включая библиотеки |

Батники, сценарий обновления и проверки прошли Windows PowerShell 5.1/CMD CI. Контрольные суммы всех 65 файлов первого Release сверены с SHA-256, рассчитанными GitHub после загрузки. Запуск самого игрового клиента требует установленного Valheim и Steam.

## Установка

1. Подготовьте отдельную папку игры для каждой сборки, рядом с её `valheim.exe`. Для новой папки используйте чистую копию игры.
2. Скачайте нужный батник из [последнего Release](https://github.com/Ammatias/Valheim-Mod-Pack/releases/latest):
   - [Midgard-Modpack.bat](https://github.com/Ammatias/Valheim-Mod-Pack/releases/latest/download/Midgard-Modpack.bat)
   - [Helheim-Modpack.bat](https://github.com/Ammatias/Valheim-Mod-Pack/releases/latest/download/Helheim-Modpack.bat)
3. Положите батник рядом с `valheim.exe`, откройте Steam и запускайте игру через этот батник.

При первом запуске скачивается весь комплект. При следующих проверяются SHA-256 и скачиваются только изменившиеся компоненты. Неизменившиеся файлы модов повторно не переписываются. Дополнительные программы и токены GitHub игрокам не нужны; используется штатный Windows PowerShell 5.1.

## Комплекты

**Midgard:** ValheimPlus, Jotunn, Warfare, Monstrum, PlanBuild, PlantEverything/PlantEasily, InventoryPlus, BetterArchery, ComboSpear, TrashItems, AutoServerPassword, ModSettings, Badgers Shading Overhaul и Skies.

**Helheim:** клиентская Yggdrasil от [Morgott](https://morgott.duckdns.org:9443/valheim/download): общая и клиентская части, включая Epic Loot, Armory, Wizardry, Seasonality, модули Morgott и клиентский интерфейс. Windows-конфиги автора; Linux-поправка серверного preloader клиенту не требуется.

## Что обновляется

- `BepInEx/plugins`, `core`, `patchers` приводятся к выбранной сборке. Посторонние файлы в этих трёх каталогах удаляются; локальные `passwords.json` сохраняются.
- Конфиги в `BepInEx/config` добавляются, если отсутствуют. Уже существующие пользовательские настройки сохраняются. Параметры, синхронизируемые игровым сервером, приходят при подключении.
- Файлы загрузчика обновляются. Сама игра, миры и персонажи не входят в комплект и не удаляются.
- Сборки не устанавливаются поверх друг друга: проверяется маркер комплекта и характерные плагины.
- Во время работы Valheim обновление запрещено. Проверка архива и всех его файлов проходит до изменения установленного комплекта. При ошибке применения выполняется откат; временные файлы успешного обновления удаляются.
- Если GitHub недоступен, ранее установленную и полностью проверенную сборку можно запустить из локального кэша. Повреждённый комплект без сети не запускается.

Сохраняемые игровые пароли не публикуются. Все сторонние моды принадлежат своим авторам; лицензии и ограничения сторонних компонентов сохраняются. Обновления в этом репозитории выпускаются отдельно от игровых серверов и от сайта Morgott: клиент и соответствующий сервер должны использовать совместимый набор.

## Публикация новой версии

Компоненты собираются из клиентского ZIP скриптом `tools/build_pack.py` с параметрами `--pack`, `--version`, `--base-url`. Для каждой версии создаётся новый тег `pack-ГГГГ.ММ.ДД.N`; опубликованные версии не перезаписываются.

Перед публикацией workflow выполняет тесты в Windows PowerShell 5.1 и CMD. Job публикации запускается для commit с префиксом `publish:` или вручную. `release-source.json` содержит временные HTTPS-адреса подготовленных манифестов; это только чтение готовых компонентов, без доступа к NAS. После публикации временная раздача выключается. Для новой версии необходимы новые доступные исходные компоненты.

Публикация сначала создаёт draft, сверяет размеры и SHA-256 всех компонентов и лишь после загрузки файлов делает Release доступным как latest.
